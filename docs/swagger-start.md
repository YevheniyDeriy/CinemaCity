# Як запустити та відкрити Swagger CinemaCity

Перевірено 2026-11-02: Swagger шлюзу відповідає 200, документи Swagger Auth, Catalog і Community генеруються. У цьому проєкті підключений **Swagger UI**. **Scalar не підключений**, тому `/scalar/v1` повертає 404. Для здачі можна використовувати наявний Swagger.

## 1. Звичайний запуск: сайт і Swagger шлюзу

1. Відкрий Docker Desktop і дочекайся стану Running.
2. Відкрий PowerShell у каталозі проєкту:

```powershell
cd E:\CinemaCity
docker compose up -d
docker compose ps -a
```

3. Переконайся, що PostgreSQL healthy, а auth, catalog, api, gateway і frontend — running. `migrate` з `Exited (0)` — це нормально: імпорт завершився успішно.
4. Відкрий:

| Що показати | Адреса |
|---|---|
| Swagger шлюзу | http://localhost:5000/swagger |
| Готовність шлюзу та залежностей | http://localhost:5000/health/ready |
| Запущений клієнт | http://localhost:5174/catalog |
| OpenAPI шлюзу | http://localhost:5000/openapi/gateway.json |

Swagger шлюзу зараз описує складений endpoint `/api/v1/screens/movies/{id}`, `/health` та `/health/ready`. **Це не об’єднана документація всіх трьох сервісів.**

У звичайному режимі адреси localhost:5001/5002/5003 з браузера не відкриваються: порти сервісів не опубліковані відповідно до ЛР3.

## 2. Показ Swagger Auth, Catalog і Community

Для цього комп’ютера підготовлено додатковий файл `.local/docker-swagger.yml`. Він тимчасово відкриває порти сервісів **лише на 127.0.0.1**. Це режим локального показу документації, а не режим перевірки закритих портів у ЛР3.

У тому самому каталозі виконай:

```powershell
docker compose -f docker-compose.yml -f .local/docker-swagger.yml up -d
```

Після запуску відкрий у браузері:

| Сервіс | Swagger |
|---|---|
| Auth: користувачі, токени, ролі | http://localhost:5001/swagger |
| Catalog: фільми, жанри, каталог | http://localhost:5002/swagger |
| Community: оцінки, рецензії, списки | http://localhost:5003/swagger |
| Gateway: складений екран | http://localhost:5000/swagger |

Не запускай одночасно локальний `Start-Local.ps1`: він використовує ті самі порти. Усі команди вище використовують уже налаштований Docker-стенд і не потребують запуску моноліту чи його редагування.

Файл `.local/docker-swagger.yml` локальний та ігнорується Git. Якщо його немає в новому клоні, створи з таким вмістом:

```yaml
services:
  auth:
    ports: ["127.0.0.1:5001:5001"]
  catalog:
    ports: ["127.0.0.1:5002:5002"]
  api:
    ports: ["127.0.0.1:5003:5003"]
```

### Як виконати авторизований запит у Swagger

1. У Swagger Auth знайди `POST /api/v1/auth/login` → **Try it out**.
2. Введи дані свого користувача та натисни **Execute**. Якщо відомого користувача немає, можна зареєструвати власного через `/api/v1/auth/register`; стандартно він отримає роль User.
3. Із відповіді скопіюй значення `accessToken`.
4. У потрібному Swagger натисни **Authorize**. Для схеми HTTP Bearer встав лише значення accessToken — Swagger сам додає `Bearer`.
5. Виконай потрібний запит. Для змін каталогу та керування ролями потрібен окремий користувач із роллю Admin; звичайний User отримує 403.
6. Для складеного endpoint візьми реальний ID фільму з каталогу й передай його в параметрі `id`.

Для основних функціональних перевірок за методичками виконуй запити через `localhost:5000` або через клієнт. Swagger окремого сервісу в цьому режимі надсилає Try it out напряму до нього, тому не доводить роботу JWT/лімітів на gateway.

## 3. Повернення до звичайного режиму ЛР3

Після показу Swagger окремих сервісів поверни базову конфігурацію:

```powershell
docker compose -f docker-compose.yml up -d
docker compose ps
```

Після перестворення контейнерів сервісні порти 5001–5003 більше не опубліковані. Для доказу закритих портів показуй саме цей режим. Swagger шлюзу на 5000 і клієнт на 5174 залишаються доступні.

## 4. Зупинка

```powershell
docker compose stop
```

Дані залишаються у volume. Для звичайної зупинки не видаляй volume і не використовуй `down -v`.

## Межі перевірки

- Базовий Docker-стенд запущений і пройшов функціональні перевірки.
- Swagger шлюзу перевірено з комп’ютера; JSON усіх трьох сервісів перевірено всередині Docker-мережі.
- Об’єднана конфігурація локального показу проходить `docker compose config --quiet`; сам додатковий режим не був увімкнений під час підготовки інструкції, щоб базовий стенд зберігав закриті порти.
- Поточні дані Docker відновлені з резервної копії від 15 жовтня; паролі старих акаунтів зберігаються як хеші, їхні відкриті значення з копії отримати не можна.
