# Порівняння поведінки ЛР2

Контрольний процес — поточний CinemaCity.API з Services:Enabled=false, без жодної правки його файлів. Новий процес — CommunityService за gateway у режимі Services. Для них створюються окремі тимчасові БД, дані Community копіюються offline-імпортером зі збереженням UUID. Тест CommunityBaseline_EightErrorContractsMatchTheUnchangedMonolith порівнює обидва процеси й записує фактичні відповіді до tests/baseline/.

| Сценарій | Моноліт | Community через gateway | Різниця |
|---|---|---|---|
| Створення оцінки | 201, JSON, Location | 201, ті самі поля, Location | Лише згенеровані ID та UTC-час |
| Редагування оцінки | 200, JSON | 200, ті самі поля | Лише згенеровані ID та UTC-час |
| Видалення оцінки | 204, порожнє тіло | 204, порожнє тіло | Немає |
| Створення без токена | 401 | 401 | Немає |
| Невідомий фільм | 404, message | 404, такий самий message | Немає |
| Бал 0 | 400, message | 400, такий самий message | Немає |
| Бал 11 | 400, message | 400, такий самий message | Немає |
| Відсутня ціль оцінки | 400 | 400, тотожне тіло | Немає |
| Одночасно фільм і епізод | 400 | 400, тотожне тіло | Немає |
| Редагування невідомої оцінки | 404 | 404, тотожне тіло | Немає |
| Видалення невідомої оцінки | 404 | 404, тотожне тіло | Немає |

Успішні відповіді нормалізуються лише за id, createdAt, updatedAt, бо це різні виконання на різних базах. Location перевіряється на точну відповідність створеному ID. Решта JSON не нормалізується. Для помилкових сценаріїв перевіряється точне тіло і код відповіді.

Додана можливість: POST з Idempotency-Key зберігає відповідь і бізнес-зміни в одній PostgreSQL-транзакції. Ключ обмежений користувачем, шляхом та query; payload перевіряється SHA-256. Transaction advisory lock серіалізує конкурентні повтори, між процесами також. Повтор повертає той самий статус/тіло/Location; інший payload з тим самим ключем — 409. Помилки не кешуються, rollback дозволяє повторити запит. Без заголовка збережена стара поведінка (зокрема 409 для дубля оцінки). Таблиця operation_replays належить лише Community.

Мережеві залежності мають дедлайн 5 секунд. Недоступність або timeout Catalog дають 503. /health перевіряє власну БД, /health/ready — також Catalog. Локальні projections — копії в БД Community, а не SQL до бази Catalog. Історичні дані про фільми оновлюються як у моноліті; штучного snapshot ціни не додано, оскільки CinemaCity не має продажу товарів/квитків.

Важливе обмеження походження: це baseline незміненого в цій сесії моноліту. Історичні відповіді перед попередньою роботою на іншому ноутбуці відсутні. Файли створені під час поточної перевірки; не стверджуємо, що вони були закомічені до попередніх змін. Архів Git d4ed8d3 збережено окремо без перезапису робочої копії.

## Свідомі зміни 2026-11-02

Додано GET /api/ratings для приватного списку операцій клієнта ЛР4. Старі POST/PUT/DELETE URL збережені. Чужа оцінка при PUT/DELETE тепер дає 404 замість старого 403 — вимога нерозкриття існування чужої операції з ЛР2; адміністративний доступ збережений. Цю відмінність перевіряє MyRatings_ArePrivateAndCancellationRemovesTheOperation. Власні 401 gateway мають ProblemDetails за ЛР3; повна уніфікація всіх legacy-помилок ще не заявляється.
