# ADR-0003: операційний сервіс Community

Дата: 2026-10-29. Статус: прийнято; основні інтеграційні перевірки пройдено.

CinemaCity — каталог фільмів з оцінками та рецензіями. Community обрано тому, що він змінює оцінки, рецензії, коментарі, уподобання та власні списки користувача і перевіряє існування фільму/епізоду через Catalog. Додавання продажу квитків створило б нову предметну область замість винесення наявної поведінки.

## Межа

| Дані | Власник | Доступ Community |
|---|---|---|
| ratings, reviews, comments, review_likes | Community | читання та запис |
| watchlist_items, user_movie_lists, user_movie_list_items | Community | читання та запис |
| catalog_statistics_outbox | Community | надійна доставка статистики Catalog |
| movies, episodes, seasons, довідники | Catalog | HTTP, локальні projections для наявних запитів |
| users, roles, refresh tokens | Auth | JWT перевіряється локально; профіль через HTTP |

Новий процес CinemaCity.CommunityService працює на 5003. Він містить власні копії вихідних бібліотек і міграцій, без ProjectReference на проєкти моноліту. Назви вихідних просторів імен залишено для зменшення ризику зміни поведінки. ServiceDefaults містить лише технічні налаштування.

Власна БД cinemacity_community задається ConnectionStrings__DefaultConnection. CINEMACITY_COMMUNITY_CONNECTION використовується лише offline-імпортером. Джерело читається у read-only транзакції; UUID зберігаються. Runtime не отримує рядок підключення до джерела. FK локальних projections знаходяться у тій самій БД, міжбазових FK немає.

Gateway у режимі Services відправляє наявні Community URL до нового процесу, а в режимі Monolith — до CinemaCity.API. Catalog отримує Community URL через Services__CommunityUrl. Моноліт, Domain, Application, Infrastructure не редагувалися під час цієї роботи; контрольні суми знаходяться в docs/monolith-sha256.json.

## Наслідки

Скопійований код можна змінювати незалежно від моноліту. Збережені старі маршрути та правила власності. Ціна — дублювання моделей і міграцій та eventual consistency статистики. Вихідні бібліотеки поки містять також непотрібні Community типи; це технічний борг, а не додаткові публічні маршрути.

Історичний baseline до попередніх змін на іншому комп'ютері відсутній. Його не можна достовірно відтворити заднім числом. Архів Git d4ed8d3 збережено окремо; він не оголошується підтвердженим останнім станом перед попередньою роботою.

Ідемпотентність реалізована в новому сервісі через operation_replays і PostgreSQL transaction advisory lock. Збереження відповіді та операції атомарне; внутрішній UnitOfWork приєднується до зовнішньої транзакції, а не комітить її завчасно. Запити без ключа зберігають вихідну поведінку.
