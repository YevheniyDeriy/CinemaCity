# Аудит ЛР0–ЛР4 — 2026-11-02

Оновлення після цього аудиту: Docker-стенд успішно зібрано, запущено та перевірено 2026-11-02. [Поточний запуск Docker](docker-run.md) уточнює наведені нижче історичні обмеження контейнерного запуску; інші висновки аудиту залишаються чинними.

Це поточна перевірка коду й запусків, а не підтвердження історії виконання. Попередні звіти від 15/29 жовтня не використовуються як доказ успішного запуску сьогодні.

## Фактичні докази

- Повний backend-набір: **26/26**, з них 15 Extraction.Tests + 7 Gateway.Tests + 4 CinemaCity.Tests. Лог: `.logs/lab4-verified-backend-tests.log`.
- Клієнт: **13/13** тестів API-шару/компонентів і production build. Тести включають concurrent 401, один refresh, відмову refresh, numeric/date Retry-After, відсутність мережі під час cooldown, помилки полів, timeout, заборону чужого API-origin, ключ повтору та подвійне натискання.
- Браузер Microsoft Edge, реальні процеси й PostgreSQL: вхід, каталог, search/empty, один composed GET, оцінка, double click, список, скасування, reload з refresh cookie. Додаткові керовані відмови: partial, 429, 401, 503 та повтор з незмінним ключем. Окремо реальні дві сторінки, debounce, мобільна ширина й logout. Код — `frontend/e2e/`.
- Резервна копія `.local/backups/cinemacity-20261015-191210.dump` відновлена в тимчасову audit-БД і перенесена справжньою утилітою. Збережено ID та хеші паролів 8 користувачів; UUID 221 позиції каталогу; 11 оцінок, 3 рецензій, 1 коментаря, 2 watchlist-записів, 5 списків і 4 позицій списків. Вихідні робочі БД не змінювалися. Тимчасові audit-БД видалено. Звіт — `.logs/lab4-archived-data.json`, повторювана перевірка — `scripts/verify-archived-data.py` (PGPASSWORD лише з середовища).
- SHA-256 маніфест захищає 96 файлів моноліту, Domain, Application, Infrastructure. Вони не змінені цією роботою. Незмінність відносно невідомого стану перед попереднім ноутбуком цим не доводиться.
- PPTX: 7 слайдів, перевірені package integrity, геометрія, шрифти, повторний import і окремі зображення всіх слайдів. Speaker notes містять виступ.
- `docker compose config --quiet` проходить. Фактичний старт контейнерів не пройдено: локальний postgres:18 повертає `exec format error` для entrypoint та psql. Навіть після явного pull linux/amd64 цей запуск не підтверджений. `/bin/sh` цього image запускається, але цього недостатньо для доказу працездатності всього стека.

## Що виправлено під час цієї перевірки

1. Запити клієнта винесені з екранів у спільний шар; legacy UI також використовує його.
2. Канонічний пошук використовує `search`, а не legacy `q`; це виявив браузерний тест.
3. CORS відкриває Retry-After/Location/Correlation браузерному JS.
4. Мережеві повтори не генерують новий ключ і не запускаються подвійним натисканням.
5. Доданий приватний список оцінок із DTO; чужі оцінки приховані відповіддю 404 при зміні/видаленні.
6. Rating/Review HTTP-адаптери відокремлені від workflow у новому сервісі, моноліт не змінений.
7. Мобільне меню з admin-роллю та довгим username більше не виходить за ширину екрана.
8. Практичний gateway deadline збільшено з 3 до 8 с: під навантаженням перше JIT/EF-виконання реально перевищувало 3 с. Керований timeout-тест окремо використовує 1 с; функціональний fixture — 15 с.
9. Залежності клієнта оновлено після npm audit; React Router оновлено до 7.18.5, returnTo також відхиляє backslash/control characters. Сумісність перевіряється повторною збіркою й браузером.

## Межа висновку

ЛР4 має реалізацію й відтворювані перевірки. Основні робочі сценарії попередніх лабораторних перевірено заново. Однак історична незмінність моноліту/давній baseline, повна уніфікація всіх legacy-помилок та живий Docker-stack не підтверджені. Тому твердження «усі пункти ЛР0–ЛР4 виконані на 100%» було б неточним.
