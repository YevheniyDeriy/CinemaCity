# Результат завершення ЛР0 та ЛР1

Дата: 2026-10-15. Початкові недоліки з [LAB_REVIEW.md](../LAB_REVIEW.md) виправлено в поточній робочій копії. Початковий аудит залишений як історичний документ, а не актуальний статус.

## Головне уточнення викладача: сервіси походять із власного моноліту

Auth і Catalog виділені з модулів, моделей та сценаріїв CinemaCity. [Першоджерела з SHA-256](extraction-origin.md) показують походження коду. У сервісах залишилися Movie/Genre, серіали, сезони, епізоди, країни, мови, персони, акторський склад, TMDb і вихідні контракти frontend. Мінімальні лабораторні URL `items/categories` позначають ці ж Movie/Genre.

Runtime сервісів не посилається на збірки моноліту або одного сервісу на інший. Обидва мають лише спільну технічну бібліотеку ServiceDefaults. Кожен має свій контекст, міграції та підключення до власної БД. Копіювання вихідних даних — окрема offline-утиліта, а не прямий доступ сервісу до чужої БД.

Фактично перенесено з локального CinemaCity:

| Дані | Результат |
|---|---:|
| Користувачі | 8; усі UUID та хеші паролів збігаються з вихідним архівом |
| Ролі вихідних користувачів | 1 Admin, 7 User; збережені як первинна роль і таблиця призначень |
| Фільми / серіали | 221; усі вихідні UUID збережено |
| Видимий каталог | 220: одна позиція вже була прихована до переходу |
| Жанри / країни / мови | 35 / 28 / 27 |
| Персони / записи акторського складу | 3243 / 3628 |
| Сезони / епізоди | 2 / 5 |
| Оцінки / рецензії / коментарі | 11 / 3 / 1; залишилися в Community |
| Власні списки / позиції списків | 5 / 4 |

Перед переходом створено читабельний PostgreSQL backup у `.local/backups`. На існуючих даних не запускали демонстраційний seed і не генерували нові паролі користувачів. Нові записи `roles` і `user_roles` заповнено зі старого enum. Наявні uploaded assets скопійовано; існуючий локальний постер перевірено через gateway і frontend — HTTP 200, image/png.

`cinemacity_lab0` — окремий навчальний знімок із власним JWT-ключем. Режим Monolith не пише в поточні бази Auth/Catalog/Community. Повторна ініціалізація перевірена: marker запобігає перезапису змін сервісів.

## ЛР0

| Пункт | Реалізація |
|---|---|
| Інвентаризація | [Модулі → сутності → таблиці → залежності → власник](inventory.md). |
| Два ADR | [Декомпозиція](adr/0001-extract-auth-and-catalog.md), [Ocelot](adr/0002-ocelot-gateway.md); контекст, альтернативи, рішення, позитивні й негативні наслідки. |
| Три діаграми | [Контейнери](diagrams/01-containers.md), [ЛР0](diagrams/02-sequence-lab0.md), [після виділення](diagrams/03-sequence-extracted.md); протоколи, порти, бази, JWT, теперішній/майбутній стан. |
| Окремий gateway | CinemaCity.ApiGateway, порт 5000, Ocelot 25.0.1, без контролерів та доступу до БД. |
| Catch-all і явні маршрути | ocelot.json; auth/users/catalog і вихідні movie/admin alias мають вищий Priority, загальний `/api/{everything}` — останній і з 0. |
| Конфігурація | Runtime downstream URL та BaseUrl беруться з appsettings/environment. ocelot.json копіюється у build/publish. |
| Health | Коротке завершення `/health` до термінального Ocelot, 200 навіть при недоступному downstream. |
| Логи | Метод, вхідний шлях, downstream без query, статус, тривалість, correlation ID. Паролі й refresh/access-токени не журналюються в нашому middleware. |
| Correlation ID | Коректне вхідне значення передається далі; інакше створюється нове; є в response. |
| CORS | Налаштовані browser origins у конфігурації; preflight обробляється gateway. |
| Помилка downstream | 503 ProblemDetails; процес gateway продовжує працювати. |
| Запуск та документація | Кореневий README, PowerShell-скрипти, docs/ADR/діаграми доступні Git. |
| Сценарій ЛР0 | Реальні GET/POST/DELETE через gateway перевірені в ізольованому тесті. На навчальному знімку також порівняно тіла прямого GET :5100 та через :5000 — однакові. |

Поточний моноліт уже містить інтеграцію ЛР1. Режим Monolith відтворює початкове проксування й оригінальні обробники, але не є твердженням, що після виконання ЛР1 його `Program.cs` залишився побайтно незмінним. Походження коду та різницю етапів описано в ADR і README.

## ЛР1

| Пункт | Реалізація |
|---|---|
| Автономні Auth/Catalog | Окремі запускаємі проєкти, 5001/5002, власні БД та набори міграцій. |
| Міграція даних | CinemaCity.DataMigration; read-only repeatable-read джерело; збережені UUID, парольні хеші та зв'язки; marker і перевірка порожньої цілі. Опційно переносить увесь Community в іншу БД/оточення. |
| User, Role, UserRole | User має IsActive/DisplayName; окремі Role й UserRoleAssignment реалізують many-to-many. Старий первинний Role залишений для сумісного UI. |
| Seed | Ролі User/Admin — у міграції; AuthSeeder створює адміністратора з переданої конфігурації. На поточних даних використано вихідного Admin. CatalogSeeder — явна опція тільки для порожнього dev-оточення; поточний каталог взято з моноліту. |
| Паролі | Оригінальний Identity PasswordHasher; вихідні хеші скопійовано, не замінено. |
| JWT | sub, jti, email, username, ID, role claims; HMAC, мінімум 32 байти, issuer/audience/lifetime/signature, 30 секунд ClockSkew. |
| Refresh | RandomNumberGenerator, у БД — хеш; ротація з блокуванням рядка й транзакцією, ReplacedByToken зберігає хеш заміни; відкликаний/прострочений refresh не приймається. |
| Пара токенів | Access/refresh та строки дії в JSON; refresh також у HttpOnly cookie для вихідного UI. |
| Auth API | Register 201/400/409; login 200/400/401, додатково вихідний lockout 423; refresh 200/400/401; захищений logout 204/401. |
| Users API | JWT-ID `/api/v1/users/me`; Admin list з пагінацією; Admin PUT roles з валідацією та 404 для відсутнього користувача. |
| Каталог | Оригінальні фільми/серіали й жанри, CRUD, soft-delete; збережені додаткові admin/series/import/search функції. |
| DTO й HTTP-шар | Канонічні Auth/Users/Catalog контролери — тонкі адаптери, без EF або бізнес-логіки. Окремі create/update DTO; додаткові вихідні маршрути також делегують сервісам. |
| Сервіси та репозиторії | IAuthService, IUserService, ICatalogService, спеціалізовані/узагальнені репозиторії та UnitOfWork. TokenService не працює з DbContext. |
| Список каталогу | page/pageSize/search/categoryId/sortBy/desc; фільтрація, сортування й Skip/Take у PostgreSQL, повертається totalCount. total збережений для існуючого UI. |
| Валідація | [ApiController]/DataAnnotations, локальні бізнес-перевірки та ValidationProblemDetails; некоректна сторінка, розмір чи пов'язані ID дають 400. Поля legacy DTO також обмежені розмірами БД. |
| Права | Читання відкрите; CRUD та керування користувачами — Admin. 401/403/201 перевірені окремо. |
| Локальна перевірка JWT | Catalog приймає токен Auth без мережевого виклику для перевірки підпису; спливлий токен відхиляється на захищеній операції. |
| OpenAPI | XML увімкнено; summary та всі коди канонічних операцій, описи DTO, схеми відповідей, Bearer UI. EF-моделі й password hash не є API-схемами. |
| Помилки | Глобальний exception handler / ProblemDetails; stack trace не віддається клієнту; старі error-result нормалізуються. |
| Логування сценаріїв | Події Auth, role changes, каталожний CRUD, імпорт, помилки; без тіл із паролями/токенами. |
| Секрети | Runtime ключі й підключення — тільки environment/ігнорований .env; у appsettings секретів немає. |
| Health | `/health` кожного застосунку, власна БД, 200/503. |
| Версія / перемикання | Нові контракти під `/api/v1`; legacy alias на Ocelot зберігають існуючий frontend; решта функцій залишається Community. |
| Зв'язки зі старими функціями | Нові UserId/MovieId/EpisodeId синхронізуються через API в локальні reference-проєкції, включно з chunked JSON-запитами. Історичний запис не дозволяє нову оцінку епізоду, який уже видалено власником. |
| Статистика оцінок | Локальна транзакція + durable outbox, повтори після відмови, монотонна версія та ідемпотентність у Catalog. |
| Контрольні питання / ціна | [Відповіді та адаптація до оригінального CinemaCity](control-questions.md). Вихідний домен не містить замовлень/ціни; правило фіксації ціни замовлення пояснено окремо. |

Порожній dev-Auth можна засіяти, задавши `Seed__Enabled=true`, `Seed__AdminEmail`, `Seed__AdminUsername`, `Seed__AdminPassword` перед його запуском. Цей шлях не запускався поверх реальних користувачів: вихідний адміністратор збережений. Довільний демонстраційний пароль не вшивається в код.

## Запущені перевірки

Основна команда — `scripts/Test-All.ps1`. Тестова база задається через CINEMACITY_TEST_POSTGRES; її назва замінюється на унікальну. Поточні бази користувача не очищаються.

- 4 вихідні інтеграційні тести моноліту: registration/login/me, публічні профілі/списки, оцінки епізодів, admin-валідація.
- 11 перевірок виділення з реальними процесами й тимчасовими БД: вихідні дані/хеші, ролі/JWT/refresh/logout, CRUD/пагінація/пов'язані ID, взаємодія нових користувачів і фільмів із Community, режим ЛР0, повторний offline-import із Community, correlation/CORS/маршрути/503, health із недоступною БД, Google redirect URI, outbox після перезапуску, відмова нової оцінки видаленого епізоду.
- 2 frontend-тести PasswordField; TypeScript/Vite production build.
- Конфігурація Docker Compose розбирається: `docker compose config --quiet`.
- На робочому native-оточенні `/health` 5000/5001/5002/5100 — 200; канонічний каталог та вихідний alias повертають 220 активних позицій; Home/recommendations — 200; власний UI показує перенесений каталог.
- Скрипти старту й зупинки перевірені на навчальному та робочому режимах; PID захищені UTC ticks від повторного використання або неправильного перетворення часового поясу.

## Межі фактичної перевірки

- Docker Engine на цьому комп'ютері недоступний. Образи й контейнерний запуск не заявляються перевіреними; конфігурацію перевірено, а ті ж застосунки перевірено native-процесами. Код і Compose готові до запуску при доступному Engine.
- Повний обмін реальним Google OAuth-кодом не виконувався. Тест перевіряє challenge, публічний gateway origin та версіонований callback без звернення до реального акаунта. Зареєстрований redirect URI має відповідати README.
- Повторний масовий імпорт із реального TMDb не запускався поверх наявного каталогу. Вихідний код імпорту перенесений; перевірки збірки й захищені маршрути є, зовнішній API залежить від чинного Tmdb-токена.
- Read-моделі й агрегати мають описану в ADR eventual consistency. Якщо власник недоступний і потрібне оновлення посилання, відповідь — 503; outbox збереженої оцінки повторюється до доставки.
