# Правила оформления веток и коммитов

Документ задает единый стиль для работы с Git в проекте CinemaCity.

---

## 1. Ветки

Название ветки пишется латиницей, в нижнем регистре, слова разделяются дефисом.

Формат:

```text
type/short-task-name
```

Допустимые типы:

| Тип | Когда использовать | Пример |
|---|---|---|
| `feature` | Новая функциональность | `feature/movie-catalog` |
| `fix` | Исправление ошибки | `fix/login-validation` |
| `docs` | Документация | `docs/database-design` |
| `refactor` | Улучшение кода без изменения поведения | `refactor/rating-service` |
| `test` | Тесты | `test/auth-service` |
| `chore` | Настройки, зависимости, инфраструктура | `chore/docker-compose` |

Правила:

- название должно коротко объяснять задачу;
- не использовать пробелы, кириллицу и спецсимволы;
- не создавать ветки с общими названиями вроде `test`, `new`, `my-branch`;
- одна ветка должна соответствовать одной логической задаче.

---

## 2. Коммиты

Коммит оформляется в стиле Conventional Commits.

Формат:

```text
type(scope): short description
```

Примеры:

```text
feat(database): add initial cinema schema
fix(auth): handle expired refresh token
docs(git): add branch and commit rules
chore(frontend): configure vite project
```

Допустимые типы:

| Тип | Значение |
|---|---|
| `feat` | Добавлена новая функциональность |
| `fix` | Исправлена ошибка |
| `docs` | Изменена документация |
| `refactor` | Изменен код без новой функциональности |
| `test` | Добавлены или изменены тесты |
| `chore` | Настройки, зависимости, сборка, инфраструктура |
| `style` | Форматирование без изменения логики |

Правила:

- описание писать на английском;
- использовать повелительное наклонение: `add`, `configure`, `fix`, `update`;
- первая строка коммита должна быть короткой, желательно до 72 символов;
- не смешивать несвязанные изменения в одном коммите;
- если изменение большое, тело коммита можно использовать для краткого списка деталей.

---

## 3. Рекомендуемая структура работы

1. Создать ветку от `main`.
2. Выполнить одну логическую задачу.
3. Проверить сборку или тесты.
4. Добавить файлы в индекс.
5. Сделать коммит по правилам.
6. Открыть pull request или слить ветку после проверки.

Пример:

```bash
git switch -c feature/project-bootstrap
dotnet build CinemaCity.slnx
npm run build --prefix frontend
git add .
git commit -m "feat(project): bootstrap backend database and frontend"
```

---

## 4. Чеклист перед коммитом

- [ ] Ветка названа по шаблону `type/short-task-name`
- [ ] Коммит назван по шаблону `type(scope): short description`
- [ ] В коммите нет временных файлов
- [ ] Сборка backend проходит
- [ ] Сборка frontend проходит
- [ ] Изменения относятся к одной логической задаче
